# 一垄一候 · AI 技术说明

> 这份文档回答三个问题：**每一层用了什么方法**、**为什么不用传统方法**、
> **哪些能力已经跑通、哪些还缺数据**。所有数字都可以用 `python run_pipeline.py` 复现。

---

## 0 系统结构：两层 AI + 一层语言层

```
① 物理内核（可解释、可审计）      ② 机器学习层（学习 + 不确定性）     ③ 语言层（转写）
────────────────────────────    ──────────────────────────────    ────────────────
地形降尺度：直减率 + 坡面辐射      参数蒙特卡洛 → 风险分数分布        规则引擎（保底）
+ 夜间冷池 + FAO-56 水量平衡      随机森林代理模型 → 概率 + 归因     LLM 提示词（可选）
                                        ↑                              ↓
                                 弱标签（来自①）/ 可换真实田间标签    地块级行动建议
```

设计原则：**判断权在①和②，语言层只负责把结论说清楚**。
LLM 不产生风险等级，避免"模型幻觉直接变成田间指令"。

## 1 层①：微气候降尺度内核

### 1.1 为什么需要降尺度

梅家坞的茶园分布在三面环山的谷地坡面上。区域气象场（Open-Meteo / ERA5）在本站尺度上
**只有一个格点**（空间方差为零），而真实茶园的微气候由地形决定：

- 坡向：南向坡日间短波收入显著高于北向坡；
- 坡位：山顶风大、蒸发强，谷底夜间冷空气堆积（冷池）；
- 坡度：决定产流比例，进而决定土壤水分的补给效率；
- 地形遮蔽：山体对日出/日落时段直射光的遮挡。

用传统物理降尺度（求解地表能量平衡）需要精确标定反照率、粗糙度、热惯量、土壤热导率，
在这类异质性强、观测稀疏的山区**参数无法闭合**。因此采用"物理骨架 + 待标定系数 + 可学习残差"。

### 1.2 温度

$$T_{\text{plot}}(t)=T_{\text{ref}}(t)+\Gamma\,(z-z_{\text{ref}})+k_{r}\big[SW_{\text{slope}}-SW_{\text{flat}}\big]^{+}_{\text{cap}}+D(z_{\text{TPI}})$$

| 项 | 含义 | 取值 / 形式 | 来源 |
|---|---|---|---|
| $\Gamma$ | 环境温度直减率 | −0.60 ℃/100 m | 山区近地层常规值 |
| $k_r$ | 短波差异→气温敏感度 | 0.012 ℃ per W·m⁻² | 复杂地形近地层观测的 1–2 ℃/100 W·m⁻² 区间；**待标定** |
| $D$ | 夜间冷池 | $-\min(0.018\cdot\max(-\mathrm{TPI},0),\,2.0)$ ℃，仅当太阳高度角 <5° | 谷地逆温经验关系 |
| $SW_{\text{slope}}$ | 坡面总短波 | 直射×地形遮蔽 + 天空散射×SVF·(1+cosβ)/2 + 反射项 | 各向同性天空近似 |

太阳位置用 NOAA 算法实现（`src/solar.py`），**已修正两处容易搞错的地方**：
① 传入当地时间必须减去时区偏移才能得到真太阳时；② 方位角须自正北起顺时针
（正午应落在 180° 附近）。这两处错误会让整张辐射图翻转，是调试中最耗时的一环。

### 1.3 湿度

露点在小尺度上比气温平滑得多，故假定**露点场均匀**，由修正后的气温反算相对湿度
（Magnus 公式，b=17.625 ℃，c=243.04 ℃）。这样"阳坡更热 → 相对湿度更低 → VPD 更高"的
耦合是自动出现的，而不是人为叠加的。

### 1.4 土壤水（FAO-56 单层桶模型）

$$S_{t+1}=\mathrm{clip}\big(S_t+P_t(1-\rho(\beta))-\mathrm{ET}_{0,\text{plot}}\cdot K_c\cdot K_s,\ 0,\ \mathrm{TAW}\big)$$

- 产流系数 $\rho=0.45+0.45\sin\beta$（截断于 0.30–0.90）：**陡坡入渗少 → 陡坡茶园先旱**；
- $\mathrm{ET}_{0,\text{plot}}=\mathrm{ET}_{0,\text{ref}}\cdot\mathrm{clip}(SW_{\text{slope}}/SW_{\text{flat}},0.25,1.6)$：阳坡蒸散更强；
- 水分胁迫系数 $K_s=\mathrm{clip}\big((S/S_{\max}-0.35)/(0.72-0.35),0,1\big)$：越干越蒸不动（自限）；
- TAW = 90 mm（0.5 m 根层、砂壤偏壤），萎蔫点 0.12、田间持水量 0.35（体积含水量）。

**预热期**：历史情景回放先跑 14 天把土壤水积分到平衡，只对评估窗口出结果，
避免初值主导结论（`run_downscaling(assess_start=...)`）。

### 1.5 已知偏差

- DEM 由约 3.5–4 m 重采样到 10 m，地坎与梯田台阶被平滑，坡面辐射差异被**低估**；
- 区域强迫场空间方差为零，所有空间差异都来自内核，因此内核的系统偏差会**整体平移**所有地块；
- 未考虑灌溉的实际情况、覆盖物、茶树冠层结构与品种差异。

## 2 层②：机器学习

### 2.1 参数不确定性传播（蒙特卡洛）

`config.ML.mc_perturb = 0.20`：对 $k_r$、$k_{\text{drain}}$、$\Gamma$ 施加 ±20% 的高斯扰动，
对热害/水分阈值施加小幅扰动，重复 N 次完整降尺度与风险评估，得到：

- **风险分数均值**（用于排序与分级）；
- **等级投票一致度**（= 预警置信度）。一致度低说明结论对参数先验敏感，应谨慎采信。

这是把"参数没标定"这件事**显式地暴露给使用者**，而不是藏在一个点估计后面。

### 2.2 风险分类代理模型（弱监督蒸馏）

**动机**：物理内核每次评估需要跑逐小时积分，且依赖一套未标定的参数；
需要一个能快速推理、能给出概率、能告诉"哪些信号真正驱动风险"的模型。

**特征**（`src/risk_model.py::BASE_FEATURES`，共 17 个，全部是运行时可获得的信号）：

| 类别 | 特征 |
|---|---|
| 地形（静态） | 高程、坡度、坡向 sin/cos、TPI、TWI、天空可视因子、log(汇流面积) |
| 辐射 | 坡面短波暴露度 (kW·h·m⁻²·d⁻¹) |
| 区域气象（动态） | 窗口最高/最低气温、降水量、ET₀ 之和、最低相对湿度、最大 VPD、连续无雨日数 |
| 土壤 | 表层体积含水量（再分析） |
| 遥感（可选） | NDVI / NDRE / NDWI 均值（需 GEE 导出，缺省不启用） |

**标签**：物理内核的风险等级（弱标签）。
**模型**：随机森林分类器（400 棵，`class_weight='balanced'`）+ 随机森林回归器（拟合风险分）。

**评估**：分层留出 25%，报告准确率、宏平均 F1、混淆矩阵、回归 R² / MAE，
以及**高风险概率的可靠性曲线**（预测概率 vs 实际频率）。

> **必须明说**：这个准确率衡量的是"代理模型复现物理内核判断的能力"（蒸馏保真度），
> **不是**田间预警精度。要得到后者，只需把 `run_pipeline.build_mode()` 返回的 `lp`
> （弱标签包）替换为真实农情标签——特征与模型代码一行不改。

### 2.3 为什么这条路线比"直接上深度学习"更稳

1. **标签根本不存在**。没有地块级的历史受害记录，任何端到端监督模型都学不出"微气候→受害"的映射；
   物理内核提供的是**有物理约束的伪标签**，可解释、可审计、可在数据到位后替换。
2. **样本量太小**。地块数 14、年份 5，直接训练深度网络必然过拟合；
   物理内核把已知定律"注入"模型，相当于极强的先验。
3. **必须有可解释性**。给茶农的建议要能说明依据，随机森林的特征重要性 + 度时/有效水等
   物理量，比黑箱网络的注意力权重更能说服人。

### 2.4 残差学习（可选模块，`src/models/downscaler_lstm.py`）

小气候站观测到位后启用。核心思想是把物理内核视为"基线"，用 LSTM 学习残差：

$$T_{\text{obs}}(t,x)=T_{\text{phys}}(t,x)+\underbrace{\text{Tanh}\big(f_\theta(\text{静态地形},\ \text{区域强迫}_{t-k..t},\ T_{\text{phys}})\big)}_{\text{有界残差}}$$

- 静态地形用 MLP 编码后广播到时间维；
- 动态序列走 LSTM（后续可换 Temporal Fusion Transformer，接口一致）；
- **有界残差**（Tanh × 可学习尺度）防止数据稀疏时模型推翻物理基线；
- 提供 MC-Dropout 推断，输出预测均值与标准差。

该模块**需要 `pip install torch`**，未安装时自动跳过，不影响主流程。

## 3 层③：行动建议（规则引擎 + LLM 解释层）

### 3.1 规则引擎（默认，保底）

规则形式：`风险类型 × 地形属性 × 物候期 → 行动项(动作, 时间窗口, 做法, 理由)`。
例如热害高风险 → 遮阳网检查 + 次日 15:00 前滴灌 25–35 min + 暂停午间作业；
复合胁迫 → 灌溉优先级最高（边际效益最大）；春季 3–4 月 → 追加防霜与采摘窗口前移。

规则引擎的可审计性对农技推广很重要：**每一条建议都能追溯到指标数值**。

### 3.2 LLM 解释层（可选，需 API Key）

`advice.build_llm_prompt()` 把地块属性、风险等级、指标证据序列化为 JSON，
配合 few-shot 示例发给任意 OpenAI 兼容接口（默认通义千问），要求输出结构化 JSON：

```json
{"地块":"MDW-03","风险等级":"高","一句话结论":"...",
 "行动":[{"序号":1,"动作":"滴灌 40 min","时间":"...","理由":"..."}],"提示":"..."}
```

提示词的硬约束：不得新增数据中没有的结论、不得夸大风险、
必须保留"辅助参考，请结合实地观察"。未配置 Key 时自动回退规则引擎，**功能不缺失**。

## 4 验证方法

### 4.1 历史灾情复盘（`src/backtest.py`）

- 用 Open-Meteo 再分析重建 2013 / 2022 / 2024 / 2025 / 2026 夏季逐小时序列；
- 用与实时模式**完全相同**的公式与阈值计算逐日风险；
- 两条累积胁迫曲线定义"致害日"：累积 >38 ℃ 度时 ≥ 30 ℃·h（热害）、
  累积土壤缺水度 ≥ 3.0（干旱，约等于连续 10 天缺水 0.30）；
- 指标口径：
  - **提前量** = 首次预警日 → 致害日 的天数；
  - **预警准确率** = "未来 7 天内累积胁迫继续增长"的预警日占比（1 − 误报率）；
  - **漏报率** = 出现胁迫增长的日期中，前 5 天内无任何预警的比例（1 − 召回率）。

### 4.2 为什么不用随机划分做验证

时序数据的随机划分会把同一次高温过程的相邻日分到训练集和测试集，
造成**信息泄漏 → 精度虚高**。正确做法是"留一年"时空交叉验证
（如用 2013/2022 训练、2024 预测），这一点已列入 `docs/验证计划.md` 第 5 周任务。

### 4.3 空间差异的量化

- **坡向四分位统计**：把适茶地形带（高程 25–230 m、坡度 4–25°）按坡向分为
  阳坡(135–225°)、阴坡(315–45°)、东坡(45–135°)、西坡(225–315°)，分别统计日最高气温与
  昼间(10–16 时)均温；
- **统一阈值盲区**（`layer_stats.blindspot`）：单一"区域<35 ℃ 时地块越阈像元占比"在极端高温情景下
  会被抹平（区域场本身也已越阈，盲区为 0）。因此改为一组互补度量，**始终有定义、不被四舍五入吃掉**：
  - `exceedance_c`：地块级最高温 − 区域气象最高温（最热地块比区域场高多少度）；
  - `silent_days` / `silent_hot_days`：区域最高温未达 35 ℃ 的天数 / 其中仍出现 ≥35 ℃ 地块的天数；
  - `hot_frac_max_pct`：这些"区域沉默日"里，最热日受影响茶园像元的占比（取最大值而非均值）；
  - `onset_silent_days` / `onset_hot_frac_max_pct`：把口径收紧到度时累积起点 32 ℃ 后的同类指标。
  这一组指标直接回答"为什么不能用区域统一阈值"：**区域场报 33.9 ℃ 时，阳坡地块已达 35 ℃**。

## 5 复现与审计

```bash
python run_pipeline.py --fast      # 约 1 分钟
```

- `outputs/run_config.json`：本次运行的全部参数（供第三方复算）；
- `outputs/run.log`：逐步日志；
- `data/raw/`：原始 API 响应与 DEM 瓦片（可离线复核）；
- **所有随机过程均固定种子且与进程无关**：`random_state=42`（随机森林），
  蒙特卡洛种子用 `crc32('meijiawu|<情景名>') % 100000` 派生。
  注意：不能用 CPython 内置 `hash(str)` —— 它逐进程随机化（PYTHONHASHSEED），
  会导致同一份输入两次运行给出不同的风险分级（本项目调试中已踩过该坑）。
  数据源为实时接口，**重新抓取**会引入天气本身的变化，这属于输入变化而非不可复现。

## 6 局限（同 README，刻意重复）

1. 地块边界为地形适宜性聚类的候选管理单元，未与 10 m 茶园分布数据集校正；
2. $k_r$、$k_{\text{drain}}$、$\Gamma$ 为文献先验，未用茶园小气候站标定；
3. 代理模型精度为相对弱标签的一致性，非田间预警精度；
4. Sentinel-2 特征接口就绪但未接入；
5. 灌溉时长需按实际设备流量二次校准。
